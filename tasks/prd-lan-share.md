# PRD：uTools 局域网分享

## 1. 产品概述

构建一个基于 React、Tailwind CSS 的 uTools 局域网分享插件。

用户可以从 uTools 分享文本、文件和文件夹，插件在本机启动临时 HTTP 服务，局域网设备通过浏览器访问站点，完成查看、下载和上传。

服务仅在 uTools 运行期间提供。关闭 uTools 后，局域网服务停止。

## 2. 已确定的产品决策

- 首版支持 Windows、macOS、Linux
- 文件和目录使用原路径引用，不复制原始文件
- 全站使用一个统一密码
- 访问站点根目录前必须完成密码验证
- 网页上传默认关闭
- 上传文件保存到插件数据目录下的 `uploads` 文件夹
- 分享项永久有效，只支持手动删除
- 服务随 uTools 启动和退出
- 原文件被移动或删除后，分享项显示为失效状态

## 3. 产品目标

- 让用户在局域网内快速分享文本、文件和目录
- 从文件管理器调用 uTools 后可以快速创建分享
- 通过二维码或链接让其他设备访问
- 提供简单可靠的密码保护
- 不修改用户原始分享目录
- 在三种桌面系统中保持一致的核心体验

## 5. 功能需求

- FR-1：系统必须支持 Windows、macOS 和 Linux。
- FR-2：系统必须支持启动、停止和自动启动局域网服务。
- FR-3：系统必须允许用户选择监听 IP 和端口。
- FR-4：系统必须处理端口冲突并显示错误信息。
- FR-5：系统必须支持文本、文件和文件夹三种分享类型。
- FR-6：文件和文件夹分享必须保留原始路径引用。
- FR-7：系统必须持久化保存分享项元数据。
- FR-8：网页根目录必须在密码验证成功后显示分享列表。
- FR-9：系统必须支持文件夹浏览和文件下载。
- FR-10：系统必须支持文本查看和复制。
- FR-11：系统必须提供可配置的网页上传开关。
- FR-12：上传文件必须保存到插件数据目录的 `uploads` 文件夹。
- FR-13：系统必须支持删除单个分享项和清空全部分享项。
- FR-14：系统必须检测源文件或目录是否失效。
- FR-15：系统必须阻止路径穿越和越权访问。
- FR-16：系统必须提供访问地址复制和二维码生成。
- FR-17：系统必须不向网页端暴露本地绝对路径。
- FR-18：服务停止后，所有网页接口必须停止响应。

## 6. 非目标

首版不包含：

- 公网分享
- 云端同步
- 用户账号系统
- 多个独立站点
- 自动过期和下载次数限制
- HTTPS 证书管理
- uTools 退出后继续运行的后台服务
- 上传到用户任意目录
- 复杂的文件协作和在线编辑

## 7. 技术设计建议

- 前端：React + Tailwind CSS
- 本地服务：Node.js HTTP 服务
- 持久化：JSON 元数据 + 插件数据目录
- 二维码：前端二维码库
- 文件处理：Node.js 标准文件 API
- 路径处理：统一使用跨平台 `path` API
- 服务模块与 React UI 解耦
- 避免依赖平台相关的原生模块

建议接口：

```text
GET    /api/health
GET    /api/shares
POST   /api/shares
DELETE /api/shares/:id
POST   /api/auth/login
POST   /api/auth/logout
GET    /api/shares/:id/content
GET    /api/shares/:id/download
POST   /api/uploads
```

## 8. 成功指标

- 用户可以在 3 步内创建文件分享
- 用户可以在 10 秒内找到并复制访问地址
- 三种系统上核心功能行为一致
- 原文件不会被上传流程修改
- 密码保护和路径访问不存在越权
- 服务启动、停止和分享列表操作稳定可用
